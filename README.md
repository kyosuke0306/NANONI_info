# NANONI_info

NANONI / 24CLUB の**関係者限定**事業情報サイト。ブランド体制・商品・原価・OEM契約条件・在庫・課題を
一覧できる内部資料を、パスワードを入れないと読めない形で公開する。

- 通常版 / 簡易版 / スケジュール / 第2ロット / AIに質問 の5ページ（目次・キーワード絞り込み・印刷/PDF出力対応）
- スマートフォン / ダークモード対応
- `noindex` 指定で検索エンジンには載らない

---

## ⚠️ このリポジトリは public です

そのため、**単なるJavaScriptのパスワード判定では意味がありません**（ソースを見れば本文が読めてしまう）。
このサイトは本文自体を **AES-256-GCM で暗号化**し、パスワードから鍵を導出してブラウザ内で復号しています。

| | |
|---|---|
| 鍵導出 | PBKDF2-HMAC-SHA256 / salt 16バイト / **310,000回** |
| 暗号化 | AES-256-GCM（IV 12バイト・認証タグ128ビット） |
| 復号 | ブラウザの WebCrypto API（`assets/app.js`） |

つまり **正しいパスワードなしでは、`payload.js` を落としても本文は復元できません。**
リポジトリには暗号文だけを置き、平文（`src/content.html`）は `.gitignore` でコミット対象外にしています。

### パスワードの扱い

**パスワードはこのリポジトリには書きません。** README や commit に書いてしまうと、
暗号化している意味がなくなります（公開リポジトリなので誰でも読めてしまう）。

関係者へは GitHub 以外の経路（口頭・チャットのDM など）で個別に共有してください。
分からなくなった場合は、パスワードを知っているメンバーに聞くか、
後述の手順で新しいパスワードに変更してください。

**より強く守りたい場合は、リポジトリ自体を private にするのが確実です。**
そのうえで GitHub Pages を使うなら、Pages の公開範囲設定（Private Pages）も併せて確認してください。
暗号化はあくまで「public のまま置くための最低ライン」です。

## 5つのページ

5つのページがあります。サイドバー下部のボタンでいつでも行き来でき、
一度パスワードを入れれば同じタブ内では再入力を求められません。

| | 内容 | 章 | 図 | 絞り込み |
|---|---|---|---|---|
| 通常版 `index.html` | 図・表・説明をすべて掲載 | 15 | 14 | あり |
| 簡易版 `simple.html` | **図だけ**（文章なし） | 4 | 7 | なし |
| スケジュール `schedule.html` | 工程・担当・優先度・小項目を**書き換える** | 2 | 1 | なし |
| 第2ロット `lot2.html` | 費用と在庫を**入れて計算する** | 1 | 3 | なし |
| AIに質問 `chat.html` | 資料を読ませてAIに聞く | 1 | — | なし |

### 章の開け閉め

**見出しを押すとその章が畳まれます。**右上の「すべて閉じる」で全部まとめて畳めます
（章が1つしかないページには出ません）。開いている / 閉じているは端末ごとに憶えていて、
次に開いたときも同じ状態になります（`localStorage` の `nanoni.folded.v1`）。

**スケジュールのページだけは、小見出し（h3）ごとにも畳めます。**
作業の内容 / 担当者ごとの担当項目 / 作業 / 作業の細分化 / 担当者 の5つです。
ガント図は畳みの外に置いてあるので、「今後のスケジュール」を開けばかならず出ます。
他のページは章（h2）だけで畳みます。

閉じたままだと中身が見えないので、次の3つでは自動的に開きます。

- 目次から飛んだとき（飛び先の章と、それを含む章）
- 検索で見つかったとき（検索をやめると元の開け閉めに戻る）
- 印刷するとき（紙は畳めないので全部出す）

**本文は1つしか持っていません。** `payload.js`（暗号化された本文）は5ページ共通で、
各ページは復号したあとに必要な部分だけを残して表示しています。
そのため資料を更新するときは `src/content.html` を直すだけで、5ページすべてに反映されます。

### スケジュールのページ

**上が「見るところ」、下が「書き換えるところ」**に分かれています。

| 上（見るだけ） | |
|---|---|
| ガントチャート | 項目名と担当。年月のある小項目はぶら下げて出す |
| 作業の内容 | 項目名 / 担当 / 優先度 / 期間 / 状態 / 内容と小項目（小項目の内容も出る） |
| 担当者ごとの担当項目 | 誰が何を持っているかをカードで一覧（未割当も1枠） |

| 下（書き換える） | |
|---|---|
| 作業 | 項目名・開始・終了・**色**・担当・優先度・状態 |
| 作業の細分化 | 内容の文章と、小項目（チェック＋内容＋予定月） |
| 担当者 | 名前の登録・削除 |

書き換えると上の表と図がその場で変わります。「全て削除する」は表ごとにあり、
その表の中身だけを消します。

#### 色は作業ごとに付けます

以前は「区分」というまとまりに色を付けていましたが、**作業そのものに色を付ける**形に
変えました（区分は廃止）。作業ごとに6色から選べます。凡例は出しません
（バーの横に項目名がそのまま出ているため）。

| | |
|---|---|
| 選べる色 | **赤 / 橙 / 黄 / 緑 / 青 / 紫** |
| 新しい作業の色 | まだ使われていない色が自動で選ばれます |

> 区分があった頃の記録は、**その区分の色が各作業に移ります**（読み込み時に自動）。

#### 作業の細分化

1つの作業を小さく分けて書けます。

- **内容** … 文章で書く。上の表にそのまま出る
- **小項目** … 完了のチェック・名前・**内容**・**開始 / 終了の年月**を持てる

**年月を入れた小項目は、図でその作業のぶら下がりとして出ます**（細いバー＋字下げ）。
年月を入れなければ図には出ず、上の表と一覧にだけ出ます。

#### 3人で共有する

**書き換えると自動で他の人にも反映されます。**「編集」の見出しのすぐ下に
「共有の設定」があります。ボタンを押す必要はありません。

**ふだんは何も表示しません。**うまくいっているときや、トークンを入れていないときは
黙っています。状態の欄が出るのは、**送れなかったとき**（ネットにつながらない・
トークンが違う）と、**ほかの人の変更を取り込んでいるとき**だけです。

> トークンを入れていない人には、共有できていないことが画面に出ません。
> 「共有の設定」を開けば `未設定` と出るので、そこで確かめてください。

データの流れは次のとおりです。

```
編集する → localStorage（自分の端末）→ 数秒後に GitHub の
          data/schedule.json を書き換える
                             ↓
              GitHub Pages が作り直す（1〜2分）
                             ↓
    他の人の画面が定期的に読みに行き、混ぜて反映する（25秒ごと）
```

- ファイルは**サイトと同じパスワードで暗号化**して置きます。
  リポジトリは public ですが、中身は読めません。
- **読む側はトークン不要**です。サイトに置かれたファイルを直接読みます。
- **書き込むにはアクセストークンが必要**です。無い人の変更は自分の画面にだけ残ります。

##### 突き合わせのしかた

丸ごと上書きはしません。**作業・小項目・担当者の1件ごとに更新時刻を持ち、新しいほうを採ります。**
消したものは「墓標」（`graves`）に残して、古い記録から復活しないようにしています。
同時に保存して衝突したときは、相手のぶんを取り込んでから送り直します。

##### トークンの作りかた（各自1回だけ）

1. https://github.com/settings/personal-access-tokens/new を開く
2. **Repository access** で `kyosuke0306/NANONI_info` だけを選ぶ
3. **Permissions → Repository permissions → Contents** を `Read and write` にする（他は不要）
4. 期限を決めて発行し、文字列をコピーする
5. スケジュールのページで「共有の設定」を開き、名前とトークンを入れて「設定を保存」

トークンはその端末の `localStorage` にだけ入り、送り先は GitHub だけです。
**トークンをリポジトリに書かないでください。**期限が切れたら同じ手順で作り直します。

> 読み込みはサイトのファイル（`data/schedule.json`）を直接見ます。
> GitHub の API には1時間あたりの回数制限があり、トークン無しで定期的に叩くと
> すぐ止められてしまうため、API を使うのはトークンがある人だけにしています。
>
> `data/schedule.json` は**誰かが最初に保存した時点で作られます**。
> それまでは共有するものが無いので、各自のひな形が出ます。

#### 色の選びかた

色は `assets/style.css` の `--ph-red` 〜 `--ph-purple`（明・暗それぞれ）にあります。
サイトの他の図で使う `--v-*`（原価・売上など意味の決まった色）とは別枠です。

> **色を足したり変えたりするときは、必ず見分けやすさを検証し直してください。**
> 6色は「どの2色を並べても見分けられるか」（全ペア）で検証済みです。
>
> | | 明るい画面 | 暗い画面 |
> |---|---|---|
> | 色覚のちがいがある場合の差 | ΔE 10.9 | ΔE 8.2 |
> | 通常の色覚での差 | ΔE 15.0 | ΔE 16.3 |
>
> （基準は 色覚差 ΔE 8 以上・通常視 ΔE 15 以上。OKLab×100）
>
> 明るい画面の黄色だけは背景とのコントラストが 3:1 に届きません。
> バーの横に項目名、中に期間が常に出ているため、色だけに頼らない形になっています。

> バーの中に出る期間の文字は、**どの色を選んでも読めるように**暗い下地を敷いています。
> 6色 × 明暗2通りで、コントラスト比 8.1〜14.5 を確認しています。

ひな形（作業名・内容・月・色・優先度・担当者）は `src/content.html` の
`data-schedule-preset` にあります（`assets/app.js` には書かない）。

> 以前の記録（進捗だけのもの、区分が無いもの、茶色の濃淡だったもの、
> 更新時刻を持たないもの）は、読み込み時に今の形へ自動で読み替えられます。

### 第2ロットのページ

第2ロットはまだ何も決まっていないので、**入力ページ**にしてあります。

- 基本の数字（本数・1ケースの本数・お店の数・卸値）を入れる
- 費用を項目ごとに入れる。単位は **1缶ごと / 1ケースごと / 1店舗ごと / 一式** から選ぶ
- 1缶あたりの原価・残るお金・回収に必要な本数が自動で出る
- 出荷先を **売る（有償） / 渡す（無償）** で足すと、残り本数が出る
- 「第1ロットの数字を入れる」で前回の金額がひな形として入る
- 「全て空欄にする」で項目ごと消して白紙から書き始める

第1ロットの実績値は `src/content.html` の `data-lot2-preset` に置いてあります
（`assets/app.js` には金額を書かない）。

> ケースの数は **本数 ÷ 1ケースの本数** を切り上げて計算します。
> そのため第1ロットを流し込むと 1缶 810.3円 と出ますが、実績は 808.9円 です
> （実際の請求は9.9ケースぶんだったため。差は1缶1.4円）。

### AIに質問するページ

復号した本文をそのまま前提知識として渡し、`claude-opus-5` に日本語で質問できます。

**APIキーは各自で用意します。** このリポジトリは public な静的サイトなので、
共通のキーを埋め込むと抜き取られます（暗号化した本文の中に入れても、
パスワードを知っている人なら誰でも取り出せるので同じことです）。
キーは各自の端末の `localStorage` にだけ入り、料金はキーの持ち主に請求されます。

1つのキーを3人で共有したい場合は、キーを預かる中継サーバーを別に立てる必要があります。

### ページごとの出し分け

図を1つ足せば通常版と簡易版の両方に出ます。表や説明文を足した場合は通常版にだけ出ます。
それに加えて、**本文側の属性で個別に指定**できます（`assets/app.js` にタイトルを
書かないので、文言を直しても壊れません）。

| 属性 | 効果 | 書く場所 |
|---|---|---|
| `data-simple="hide"` | 簡易版では表示しない | `<section>` または `<figure class="viz">` |
| `data-simple-title="…"` | 簡易版でだけ別の見出しにする | `<h2>` |
| `data-page="…"` | その専用ページにだけ出す（`schedule` / `lot2` / `chat`） | `<section>` |
| `data-schedule-preset` | スケジュールのひな形（作業・月・色・優先度・担当者） | スケジュールの章 |
| `data-schedule-chart` | ガント図を差し込む位置 | スケジュールの章 |
| `data-lot2-preset` | 第2ロットのひな形になる第1ロットの実績値 | 第2ロットの章 |

```html
<!-- 簡易版には出さない図 -->
<figure class="viz" data-simple="hide"> … </figure>

<!-- 簡易版には出さない章 -->
<section id="license" data-simple="hide"> … </section>

<!-- 専用ページにだけ出す章 -->
<section id="schedule" data-page="schedule"> … </section>
<section id="lot2"     data-page="lot2">     … </section>

<!-- スケジュールのひな形になる1件 -->
<span data-task="license" data-name="免許 申請〜取得" data-priority="high"
      data-from="2026-10" data-to="2026-11" data-color="y"
      data-detail="一般酒類小売業免許。審査に約2ヶ月。"></span>

<!-- 担当者のひな形 -->
<span data-member="m1" data-name="担当A"></span>
```

図が1つも残らない章は、簡易版では章ごと表示されません。
簡易版の見出しからは章番号を自動で外しています（通常版と番号がとびとびになるため）。

## 中身を書き換える

平文はリポジトリに入っていないので、**復号 → 編集 → 再暗号化**の順で作業します。

```bash
pip install cryptography          # 初回のみ

# 1. payload.js から本文を復元（パスワードを聞かれる）
python3 tools/build.py decrypt --in payload.js --out src/content.html

# 2. src/content.html を編集
#    <section id="..."> と <h2> を足すだけで、目次には自動で追加される

# 3. 再暗号化（payload.js を更新）
python3 tools/build.py encrypt --in src/content.html --out payload.js

# 4. コミット & プッシュ（src/content.html は .gitignore 済みなので入りません）
git add payload.js && git commit -m "資料を更新" && git push
```

### パスワードを変更する

上の手順3で新しいパスワードを入力するだけです。`payload.js` を作り直せば古いパスワードは無効になります。
変更後は、新しいパスワードを関係者へ GitHub 以外の経路で共有してください。

> **注意**：うっかりパスワードを commit してしまった場合、後のコミットで消しても
> 履歴からは読めてしまいます。その場合は履歴を書き換えたうえで、
> パスワード自体も新しいものに変更してください（漏れたものとして扱う）。

#### 作りかたの決まりごと

実機で1つずつ試して分かったことです。**外すとホーム画面でぼけます。**

| | 理由 |
|---|---|
| **暗い地に明るい絵柄**にする | 端末の「アイコンの外観」がダークだと、iOS が画像全体を暗い側へ潰す。白地に黒い絵柄だと絵柄が地に同化して読めなくなる |
| **180×180 ちょうど**にする | 512×512 を置いたら iOS がぼかして描いた |
| **RGB のまま**扱う（白黒に変換しない） | 綺麗に出ているサイトの画像がそうだった |
| 縮小は **Pillow の LANCZOS** | ブラウザで縮小したものはぼけた |
| 白い紙に重ねて**アルファを捨てる** | 透明を残すと iOS が黒く塗りつぶす |

> 以前はブラウザ（Playwright）で画面を撮って書き出していましたが、
> それだとホーム画面でぼけました。Pillow で縮小する形に変えています。

原本は **1024×1024 の正方形**にしてください。
**地はべた塗り**にすること（白でも暗い色でもかまいません。四隅から読み取ります）。
角丸は付けないこと。iOS も Android も端末側で角を丸めます。

**アルファ（透明）は残しません。** iOS は透明部分を黒で塗りつぶすので、
残っていると**ホーム画面で黒い四角**になります。
`make-icons.py` は白い紙の上に重ねてから書き出すので、原本に透明があっても
白で塗りつぶされ、アルファの無い PNG になります。

**絵柄は中心から半径40%の円に収めてください。** Android は丸く切り抜くので
（`site.webmanifest` の `purpose: "any maskable"`）、はみ出すと欠けます。
`check-icons.py` がこの3点をまとめて確かめます。

```
[OK] icon-src.png           1024x1024 RGB  透明なし=True  絵柄の広がり=37.7%（上限 40%）
[OK] apple-touch-icon.png   180x180 RGB    透明なし=True  絵柄の広がり=37.8%（上限 40%）
[OK] icon-192.png           192x192 RGB    透明なし=True  絵柄の広がり=37.8%（上限 40%）
[OK] icon-512.png           512x512 RGB    透明なし=True  絵柄の広がり=37.7%（上限 40%）
```

> 綺麗に出ているサイトの画像と、色数・にじみ・ファイル形式まで揃えてあります。

アイコンの割り当ては次のとおりです。

| 対象 | 使われるファイル | 指定場所 |
|---|---|---|
| iOS（ホーム画面） | `assets/apple-touch-icon.png`（180×180） | `index.html` の `apple-touch-icon` |
| iOS（アイコン下の名前） | — | `index.html` の `apple-mobile-web-app-title` |
| Android Chrome | `assets/icon-192.png` / `icon-512.png` | `site.webmanifest` |
| Android（表示名） | — | `site.webmanifest` の `short_name` |
| ブラウザのタブ | `assets/favicon.svg` | `index.html` の `rel="icon"` |

> **タブ用は SVG にしてあります。** 小さい PNG を favicon にすると、
> **iOS がホーム画面のアイコンをその小さい画像から作ってしまい**、
> 引き伸ばされてぼけます。実機で観測したふちの幅 5.8画素は、
> 32px を 180px へ引き伸ばしたとき（5.2画素）とほぼ一致していました。
> SVG なら何倍に描かれても大きさに縛られません。
> 絵柄は図形ではなく画像なので、512px の PNG を中に埋め込んでいます
> （`make-icons.py` が自動で作ります）。

> **iOS は manifest を見ません。** `apple-touch-icon` の PNG がないと、
> ホーム画面にはページのスクリーンショットが縮小されて置かれます。

#### 「アプリとして開く」指定は付けません

付けると、**端末が暗い外観のとき iOS がアイコンを勝手に暗く落とします。**
白い地が灰色になり、その上の黒い絵柄が沈んで薄く見えます。
画像は白いままなので、直すには指定のほうを外すしかありません。

外してあるのは次の3つです。

| 外したもの | 何をするものだったか |
|---|---|
| `<meta name="apple-mobile-web-app-capable" content="yes">` | iOS でアプリのように全画面で開く |
| `<meta name="apple-mobile-web-app-status-bar-style" …>` | 上記のときの時計まわりの色 |
| `<meta name="mobile-web-app-capable" content="yes">` | Android 側の同じ指定 |

`site.webmanifest` の `display` も `standalone` から **`minimal-ui`** にしてあります。
`standalone` のままだと、meta を外しても Safari が manifest を見てアプリ扱いにするためです。

> 同じ絵柄・同じ白背景で白いまま出ている `kyosuke0306/NANONI_home` に合わせた形です。
> あちらもこれらの指定を持たず、`display` は `minimal-ui` です。

**代わりに、ホーム画面から開くと Safari の細い操作バーが出ます**（全画面では開きません）。
全画面のほうがよければ `apple-mobile-web-app-capable` を戻せますが、
そのときはアイコンが暗く落とされる状態にも戻ります。

> それでも暗いままのときは、端末側の設定が優先されています。
> ホーム画面を長押し →「編集」→「カスタマイズ」で、アイコンの外観が
> **ダーク / 自動**になっていないか確かめてください（**ライト**にすると白いまま出ます）。

> 絵柄が図形ではなく画像なので、SVG のアイコンは置いていません
> （拡大しても綺麗にならないため、PNG だけにしてあります）。

> **アイコンを変えても端末側では古いまま表示されます。**
> iOS・Android とも強くキャッシュするため、確認するときは
> **ホーム画面から一度削除して、追加し直してください。**

## 使い方のメモ

| 操作 | 動作 |
|---|---|
| `/` キー | キーワード絞り込みにフォーカス（通常版のみ） |
| `Esc` | 絞り込み解除 / モバイルの目次を閉じる |
| 「印刷 / PDF」 | 目次やボタンを除いた印刷レイアウトで出力 |
| 「ロック」 | 復号状態を破棄してロック画面に戻る |

解錠状態は**同じタブの間だけ**保持されます（タブを閉じると再入力）。
